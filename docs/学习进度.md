**首次全绿**：2026-09-24，Run #5（commit `3d5e31f`），14 步全 success，耗时 49 秒。
仓库：<https://github.com/AmazingYe-oss/gin-vue-admin-autotest>

**一处实现偏差**：原计划用 `docker compose` 起环境，实际改为 `docker run` + 启动脚本。
原因：gva 不是 `up -d` 就能用的服务 —— 它必须先调 `/init/initdb` 灌种子数据（否则库里连 admin 用户都没有，登录直接报「用户名不存在」），再改数据库里的验证码开关才能登录。这些属于「一次性初始化动作」，写在启动脚本里比塞进 compose 更清楚。

**踩坑（三个，同一类根因）**：CI runner 的 uid 是 1001，容器内 gva 以 uid 1000 运行；绑定挂载不改变文件属主，于是：

1. **镜像 digest 打印报错** —— `{{join .RepoDigests ","}}` 类型不匹配 → 改用 `{{json .RepoDigests}}`
2. **initdb 返回 `code:7`「自动创建数据库失败」，但容器日志显示「初始数据成功」** —— 自相矛盾。实为最后一步 `WriteConfig()` 回写 `config.yaml` 失败（宿主机属主 644，容器内 uid 1000 只读）→ `chmod 666 config.yaml`
3. **改验证码时报 `sqlite3.OperationalError: readonly database`** —— `gva.db` 由容器内 uid 1000 创建、权限 644，宿主机 uid 1001 写不了 → initdb 后 `docker exec -u 0 chmod 666 /app/data/gva.db*`

**这类问题本地默认复现不出来**：WSL 的 uid 恰好也是 1000，与容器一致。是「本地能跑、CI 报错」的典型样本，值得单独整理成面试素材。
